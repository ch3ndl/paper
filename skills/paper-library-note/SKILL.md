# 论文精读 → Saline Papers

为用户的论文库制作可以独立阅读、可追溯原文、可上传网站的详细笔记。默认中文。这个任务的重点是按原文顺序讲透论文，不是围绕少数贡献重新写摘要。网站公开仓库为 `ch3ndl/paper`；生成内容不等于获得发布授权。

## 阅读与内容组织

先读取 [references/format.md](references/format.md) 确认网站数据约定，再读取用户论文正文与可取得的关键图表。以原文真实标题建立章节清单，保留原文节与小节顺序；不要把自己重排的“背景—方法—结果”结构标成原文章节。大型章节可包含多个 blocks，小节名称放在 block.heading 中。必须能看出原文章节、小节如何对应到笔记。综述、理论论文按其自己的论证结构处理。

正文 explanation 是精读主体，通常占主要篇幅：逐节交代本节解决什么问题、作者具体做了什么、为何这样设计、观察到什么、如何接到下一步。方法保留影响解释与复现的样本/数据来源、筛选与划分、对照、关键参数、统计口径；结果保留比较条件、关键数值、单位、图表和不支持预期的结果。解释首次出现的关键术语，复杂公式先讲符号、直觉和适用条件。不要用几句“该段的逻辑功能”替代内容讲解。

每个方法和结果小节都要有对应讲解；一个小节有多项实验时按实验展开 blocks。以把研究讲明白为准，不用短字数上限压缩正文，不为凑长篇补无关背景。跨节重复信息只简要回指。主要图表就近放入对应论证段，解释横纵轴/分组/面板、比较方法、关键趋势和结论边界；不能只写“如图所示”。表格可用正文逐项解释核心比较与数值，避免只截一张看不清的表。

analysis 放独立评议：明确“作者解释”“AI 分析”及证据边界；说明限制具体影响什么结论，保留反例。englishParaphrase 是可选英文改写，绝不冒充原句；quote 仅用于确需保留的短原文摘录并在本节标明位置。可用自己的讲解替代长段复制，按实际许可处理全文翻译与图像再发布。

coverage 如实列明读过的正文/附录/补充材料和未覆盖部分。无法取得正文时只按摘要生成部分笔记，标为 draft，明确缺失范围；不得虚构页码、数值、图表和补充结果。status 默认 draft；只有用户明确已人工核对才可设 reviewed。未经验证的推断不能通过标记“AI”变成事实。

## 分类、图片与输出

分类只放一个研究主题，标签放多个有区分度的主题/方法/任务；优先沿用用户已有分类命名。没有偏好时自行选合适分类和 3–6 个标签。slug 使用稳定的英文小写连字符标识。

图片下载实际论文图像，保存为 `assets/images/<slug>/figure-1.jpg` 等本地文件，支持 PNG/JPEG/WebP。逐图保留图号、作者、来源链接、许可及必要的第三方署名；改动图像要注明。无法取得或再发布许可不清楚时，先不嵌入，正文写出缺口和来源链接，不生成假图替代论文证据。不使用外部热链、占位路径、浏览器验证码截图或带访问令牌的签名 URL。示意图如果自行绘制，明确标注为重绘，不伪装成论文原图。

在一个输出目录内生成 `notes/<slug>.json` 和对应图片目录。使用 `scripts/package_note.py <输出目录> <slug> <输出ZIP绝对路径>` 校验并打包；脚本只收录该笔记实际引用的图片。导入网站时上传该 ZIP；直接发布到 GitHub 时合并 ZIP 里的两个目录。多篇论文一篇一个包。

交付前对照原文目录检查覆盖，核对关键数值的比较条件、图号与出处，确认引用图片实际存在且可打开，再运行打包脚本。交付 ZIP 链接，简要说明分类、标签、原文覆盖范围与仍需核对之处。用户没有要求发布时停在文件交付，不连接仓库或上传。
