# 论文精读 → Saline Papers

为用户的论文库制作可独立打开的双栏批注 HTML，并导出可上传网站的文件包。默认左栏为英文原文与对应中文译文，右栏为逐段中文批注及详细讲解。网站公开仓库为 `ch3ndl/paper`；生成内容不等于获得发布授权。

## 阅读与内容组织

先读取 [references/format-v2.md](references/format-v2.md) 确认双语批注数据约定，再读取用户论文正文与可取得的关键图表。以原文真实标题建立章节清单，保留原文节、小节、段落及论证顺序；不能以重新写的摘要或自选论证单元代替原文段落。过长原段可按句群拆分，但必须连续覆盖并明确原文位置。小节名称放在 block.heading 或 sourceLocation 中。综述、理论论文按自己的论证结构处理。

每个 block 的 english 必须是实际读取并核对的英文原文，不能生成英文改写冒充原句；translation 必须完整对应这段英文，意译为主，保持中文学术表达流畅，保留量词、否定、限定、引用编号、数值和单位。不要用概括性摘要代替翻译。explanation 是额外的详细中文讲解，不能把它与作者原文或译文混写。

explanation 解释本段研究内容与前后关联：为什么这样设计、数据或方法具体如何工作、指标如何读、结果支持什么。保留影响解释的样本、筛选与划分、对照、参数、统计口径及反例。关键术语首次出现给出解释，复杂公式讲符号、直觉和适用条件。不要用几句“该段的逻辑功能”替代详细内容，也不以固定字数上限压缩论文。

每个方法和结果小节都要有对应讲解；一个小节有多项实验时按实验展开 blocks。以把研究讲明白为准，不用短字数上限压缩正文，不为凑长篇补无关背景。跨节重复信息只简要回指。主要图表就近放入对应论证段，解释横纵轴/分组/面板、比较方法、关键趋势和结论边界；不能只写“如图所示”。表格可用正文逐项解释核心比较与数值，避免只截一张看不清的表。

每段 annotation 都有三项：function（段落功能，如引出问题、提供证据、反驳异议或总结）；role（在全文论证链中的具体位置）；critique（值得注意的论证技巧或潜在漏洞，并说明影响哪类结论）。区分作者解释、AI 分析和直接证据，不机械给每段编造漏洞。

highlights 只标在英文原文中，使用五个维度：thesis 黄色=核心论点，term 红色=关键概念/术语，evidence 蓝色=实证证据/数据，concession 绿色=让步/反驳处理，method 紫色=方法论说明。挑选实际承担该逻辑功能的关键片段；不需要每段强行凑满五类。高亮文本必须是 english 中精确存在、彼此不重叠的子串。中文译文不高亮。

结尾 argumentMap 必须包含问题→论点→证据→反驳/限定→结论的全文逻辑骨架，以及作者核心主张的一句话版本、论证最强处和最弱处各一条。没有真正反驳时如实写作者的限定，不虚构对手观点。course 使用用户提供的课程信息；未提供时用“学术论文精读 · 论证结构与逻辑分析”等通用阅读栏目，不虚构学校、课程号或教师。

复用原文和完整翻译前核实实际许可。用户提供原文或明确开放许可支持时，可按许可制作；对于未获授权的付费全文，不以“AI 改写”冒充原文填满页面，应说明可用范围并请求所需原文或授权。无论何种情况都不伪造原句。

coverage 如实列明读过的正文/附录/补充材料和未覆盖部分。无法取得正文时只按摘要生成部分笔记，标为 draft，明确缺失范围；不得虚构页码、数值、图表和补充结果。status 默认 draft；只有用户明确已人工核对才可设 reviewed。未经验证的推断不能通过标记“AI”变成事实。

## 分类、图片与输出

分类只放一个研究主题，标签放多个有区分度的主题/方法/任务；优先沿用用户已有分类命名。没有偏好时自行选合适分类和 3–6 个标签。slug 使用稳定的英文小写连字符标识。

图片下载实际论文图像，保存为 `assets/images/<slug>/figure-1.jpg` 等本地文件，支持 PNG/JPEG/WebP。逐图保留图号、作者、来源链接、许可及必要的第三方署名；改动图像要注明。无法取得或再发布许可不清楚时，先不嵌入，正文写出缺口和来源链接，不生成假图替代论文证据。不使用外部热链、占位路径、浏览器验证码截图或带访问令牌的签名 URL。示意图如果自行绘制，明确标注为重绘，不伪装成论文原图。

在输出目录内生成 schemaVersion 2 的 `notes/<slug>.json` 和对应图片目录。使用 `scripts/package_note.py <输出目录> <slug> <输出ZIP绝对路径>` 校验并打包；脚本自动生成 `html/<slug>.html`，将样式、交互与图片内嵌为一个完整文件，同时把 JSON 和实际引用的图片装入 ZIP。必须同时交付独立 HTML 和网站导入 ZIP。网站上传 ZIP；直接发布到 GitHub 时合并其中 notes/ 和 assets/。多篇论文一篇一个包。

默认渲染保留深海军蓝顶部、标题和课程栏、五色图例、sticky 章节导航；左栏英文在上、中文译文在下，中间 1px 细线，译文背景 #f0ece2 加左侧细竖线；右栏批注卡带色边；底部论证总览；移动端按每段的英文→译文→批注顺序单栏展示。字体可按用户偏好调整，不以字体替代对内容与结构的遵守。

交付前逐段核对英文与原文，检查译文没有漏掉条件、否定或数值；对照目录检查覆盖；核对关键数字、图号、表注及出处，确认图片文件可打开。运行打包脚本并打开 HTML 检查双栏、段落对应、五色高亮、sticky 导航和移动端顺序。交付 HTML 与 ZIP 链接，说明分类、标签、覆盖范围和缺口。用户没有要求发布时停在文件交付。
